# CivicGuards / ArtiProof — Audit (2026-05-09)

Five parallel agents reviewed the backend (security + correctness), frontend, tests / CI / deploy, and performance. Findings below are filtered: I dropped 4 inaccurate agent claims (e.g., "no migrations exist" — false, 0001–0009 are present; "missing ownership validation in /generate" — false, ids are checked) and merged duplicates that surfaced in multiple audits.

The current state of the codebase is **broadly functional but not production-hardened**. 210 backend tests pass; the frontend type-checks clean and is deployed. The issues below are the gap between "ships and works in dev" and "safe under load with adversarial input."

## TOP 10 — fix in this order

| # | Severity | Area | What | Why now |
|---|---|---|---|---|
| 1 | CRITICAL | Security | **HTML injection in PDF renderer.** `app/services/report_engine/html_template.py` interpolates user-controlled fields (`claim_text`, `explanation`, `true_version`, `original_citation`, `researcher_name`, `institution`, annotation `text`, branding `name` / `logo_url`) into HTML via f-strings. The module never imports `html.escape`. Attackers can inject `<script>` or `<img onerror=…>` into a report that any other user views via a share link. | Public share endpoint exists; any logged-in user (or anyone with the share token) can be targeted. |
| 2 | CRITICAL | Ops | **Celery worker + beat are not running in production.** `backend/railway.toml` only starts `uvicorn`. No Procfile, no separate worker service. The scheduled-reports sweep, cleanup task, and any other Celery beat job will never execute on Railway. | The whole "scheduled reports" feature ships as dead code today. |
| 3 | CRITICAL | Security | **SSE streams unauthenticated.** `GET /api/source-check/{id}/stream` and `GET /api/researcher/{id}/stream` skip auth ("TODO security phase 5") because EventSource can't send `Authorization`. Any user with an ID can trigger expensive Gemini pipeline runs on others' records. | Easy to abuse for cost-amplification + data exfiltration of streamed payloads. |
| 4 | HIGH | Security | **SSRF via `branding.logo_url`.** User supplies arbitrary URL; no validation against internal IPs, link-local (`169.254.169.254` metadata service), `localhost`, or non-HTTP schemes. WeasyPrint fetches the URL during render. | Cloud metadata token theft is the canonical attack. Branding endpoint is team-tier-gated, but team members can still hit it. |
| 5 | HIGH | Perf | **Synchronous PDF/HTML render blocks the event loop.** `html_to_pdf(html)`, `save_pdf(...)`, `os.remove(...)` run directly in async routes (`app/routers/reports.py`). One slow PDF freezes every concurrent request on that worker. | Will manifest as p99 latency cliff under load. |
| 6 | HIGH | Tests / CI | **No CI/CD pipeline.** `.github/workflows/` does not exist. Nothing gates broken tests, broken type-checks, or failed migrations from reaching `main` and deploying. | `pytest` passes today, but the next regression won't be caught before users see it. |
| 7 | HIGH | Perf | **Sequential per-item loads in `/generate` for comparison + audit templates.** The list comprehension `[await _load_check_data(c, db) for c in checks]` issues 2 queries per item × N items. Combined with synchronous PDF render in the same request, comparison/audit reports will time out at moderate N. | Already-shipped feature; first user to pick 10 sources gets 20+ sequential round-trips. |
| 8 | HIGH | Security | **Health check doesn't verify dependencies.** `/health` returns 200 unconditionally. Railway can't auto-restart on a Postgres or Redis outage; degraded prod is invisible. | Outage detection depends on user reports today. |
| 9 | MEDIUM | Correctness | **`_next_run()` lies about its behavior.** Docstring says "aligns to ~9am UTC"; implementation just adds 7/30 days from now. Reports fire at creation-time-of-day forever. | Cosmetic bug today, but observable once feature actually runs (issue #2). |
| 10 | MEDIUM | Tests | **Happy-path coverage missing on the new endpoints.** Schedules CRUD, branding PUT, annotations PUT, scheduled-reports sweep with non-empty input — only rejection paths are tested today. | Refactors here will silently break user-visible behavior. |

## Full findings, grouped

### Security (verified subset of agent's 23)

- **CRITICAL** — HTML injection in PDF renderer (#1 above).
- **CRITICAL** — SSE endpoints unauthenticated (#3 above): `app/routers/source_check.py` `:317`, `app/routers/researcher.py` `:236`.
- **HIGH** — SSRF via `branding.logo_url` (#4 above). Add allowlist + reject `localhost` / `169.254.x.x` / `10.x.x.x` / `127.x.x.x` / non-HTTPS / `file://`.
- **HIGH** — Share tokens never expire. `Report.share_token` lasts forever. Add `share_expires_at` + cleanup task.
- **MEDIUM** — Demo seed credentials reachable in any non-prod environment (`app/routers/seed.py`); guard with an explicit `ENABLE_SEED_ROUTES` env flag, not just `ENVIRONMENT != "production"`.
- **MEDIUM** — Notification-prefs JSON not validated against a schema before write; arbitrary keys persist.
- **MEDIUM** — TOTP backup codes don't rotate after consumption (advisor likely caught: confirm by reading `app/routers/security.py` 2FA login).
- **LOW** — `/health/detailed` (or equivalent) leaks which integrations are configured.
- **LOW** — No account lockout after N failed logins; rate limit alone allows distributed brute force across accounts.
- **LOW** — JWT secret can default to weak value in non-prod; harden the startup check.
- **NOTE — dropped from agent claims:** "missing CSRF" (we use Bearer tokens, not cookies, so CSRF doesn't apply); "register accepts admin role" (verified safe — role is forced to "researcher"); "share token predictable" (uses `secrets.token_urlsafe(32)`, fine).

### Correctness

- **HIGH** — `await db.commit()` in `app/tasks/scheduled_reports.py:180` is *outside* the per-schedule try/except, so a single failing schedule rolls back the whole sweep batch. Move commit inside the loop or use SAVEPOINTs.
- **HIGH** — `app/routers/reports.py` regenerate path: when a report's underlying source check is soft-deleted (`deleted_at IS NOT NULL`), the share-link download still serves it. Add the soft-delete filter to `_serve_report_pdf` joins.
- **MEDIUM** — `_summary_check_data` guards `if not checks` then still does `sum(...) / len(checks)` only inside the else branch — actually safe, but confusing; collapse to one branch.
- **MEDIUM** — `_annotations_html` skips dicts with no `text`, but unguarded if `annotations` contains non-dicts (legacy seed data). Use `isinstance(a, dict)` + `.get(...)`.
- **MEDIUM** — `_next_run()` 9am-UTC comment lie (#9 above).
- **LOW** — `app/routers/reports.py` PDF cache invalidation on annotation update: `pdf_path = None` is set, then `commit()` happens 2 lines later. Concurrent download in that window serves stale PDF.
- **NOTE — dropped:** "no migrations exist" (false: 0001–0009 present); "register endpoint vulnerable to admin role injection" (false).

### Performance

- **HIGH** — N+1 in `comparison` + `institutional_audit` generate paths (#7 above). Replace with one query that joins claims + citations / publications.
- **HIGH** — Block-the-loop sync calls (#5 above): `html_to_pdf`, `save_pdf`, `os.remove`. Wrap with `asyncio.to_thread(...)` or move to a Celery task and return 202 + poll.
- **HIGH** — Gemini calls in `app/services/report_engine/narrative_generator.py` have no timeout, no retry, no backoff. One slow call wedges the request thread.
- **MEDIUM** — Missing composite indexes on hot read paths:
  - `claim_analyses (source_check_id, created_at)`
  - `publication_analyses (researcher_profile_id, year)`
  - `reports (user_id, created_at)` for the list page
  - `report_schedules (active, next_run_at)` for the daily sweep
- **MEDIUM** — `report_schedules` count cap fetches all rows then `len()` instead of `SELECT COUNT(*)`.
- **MEDIUM** — JSON columns (`pinned_items`, `watchlist`, `linked_providers`, `annotations`, `source_check_ids`) lack server-side size caps. Cap at the route layer (already done for some) and add a DB CHECK as belt-and-suspenders.
- **LOW** — Settings page is a 2,500-line client component. Code-split by section so initial render only ships Profile + Notifications.

### Frontend

- **MEDIUM** — `src/lib/auth.ts` JWT callback uses bare `as` casts on backend response shape; backend changes silently break sessions.
- **MEDIUM** — Settings page fires both `setError(msg)` AND `toast.error(msg)` for the same failure; users see a duplicate.
- **MEDIUM** — `apiFetch` 401 → `signOut()` only checks `typeof window`; harden against being called during SSR.
- **MEDIUM** — Compose dialog list (multi-select for comparison/audit) lacks a `max-height` constraint; long lists overflow the dialog.
- **MEDIUM** — Several icon-only buttons missing `aria-label` (close button on Dialog, ExternalLink in reports list).
- **MEDIUM** — `refresh()` in reports page useEffect has empty deps but the function isn't memoized → stale-closure risk if the file gets refactored.
- **LOW** — `analysis_preferences.ai_detection_model` field still serialized into PUT requests after I removed the UI; harmless (backend ignores unknowns), but worth dropping from the frontend type.
- **LOW** — Settings page TODO ("wire client-side Google Identity Services") — connect-Google flow is text-only.
- **LOW** — Several places do `await res.json().catch(() => ({}))` followed by `as { detail?: string }` — extract a `parseError(res)` helper.
- **NOTE — dropped:** "no E2E tests" is true but I'd file it under Tests / CI rather than Frontend.

### Tests / CI / Deploy

- **CRITICAL** — Celery worker + beat not running (#2 above). Add a separate Railway service (or Procfile entry) running `celery -A app.tasks.celery_app worker --beat --loglevel=info`.
- **CRITICAL** — No `.github/workflows/`. Add CI that runs `pytest`, `ruff check`, frontend `tsc --noEmit`, and `alembic upgrade head` against a clean Postgres.
- **HIGH** — Health check doesn't ping DB / Redis (#8 above).
- **HIGH** — Missing happy-path tests (#10 above).
- **HIGH** — No frontend tests at all. Add Playwright with at least the smoke flow: log in → run a source check → generate report.
- **MEDIUM** — `REPORT_SWEEP_HOUR_UTC` is read but not in any `.env.example`. Add to repo-root `.env.example` (only one exists).
- **MEDIUM** — No `frontend/.env.example`. Devs guess at `NEXT_PUBLIC_API_URL`, `NEXTAUTH_SECRET`, etc.
- **LOW** — README test count and feature list lag the current state.
- **LOW** — Migration rollback (`downgrade()`) is never tested. CI step: apply head, downgrade by one, re-apply, on a fresh Postgres.

## What's *not* a problem (for the record)

- **Migrations exist and run on deploy.** `railway.toml` does `alembic upgrade head` before `uvicorn`. The correctness agent claimed otherwise; that was wrong.
- **Generate endpoint ownership checks are present.** Every supplied id is checked against `current_user.id`. The correctness agent claimed this was missing; it isn't.
- **Share tokens are unguessable.** `secrets.token_urlsafe(32)` is fine; rotation/expiry is the real gap, not predictability.
- **CSRF doesn't apply** because the API is bearer-token-authenticated, not cookie-authenticated. Several agents flagged this anyway.
- **Backend tests pass clean (210/210)**, frontend type-checks clean, prod deploy is live at `artiproof.vercel.app`.

## Suggested ordering for the work

If shipping these one PR at a time, I'd group like this:

1. **PR 1 — security hardening (top 4):** escape PDF renderer fields, lock down SSE streams, validate `logo_url` for SSRF, add expiry to share tokens.
2. **PR 2 — Celery + CI:** add the worker/beat service, add `.github/workflows/ci.yml`, fix `_next_run()` actually align to 09:00 UTC, add the missing happy-path tests in the same PR so CI has something to gate on.
3. **PR 3 — perf:** wrap `html_to_pdf` / `save_pdf` in `asyncio.to_thread`, batch the comparison/audit loads, add the four composite indexes as a new Alembic migration (0010).
4. **PR 4 — health + ops:** real health endpoint with DB + Redis ping, frontend `.env.example`, README refresh.
5. **Backlog:** the LOW/MEDIUM frontend items and observability gaps.

Total: ~25 actionable items, ~4 PRs to land them all.
