# Phase 3 — Report Generation & Recommendations Engine

## Context
Read `00-PROJECT-BRIEF.md` for full context. Phase 2 (security scanner) is built. Now we build the **report generation engine** — the layer that turns raw scan data into plain-language, actionable security reports that non-technical staff at civil society organizations can understand and act on.

## Objective
Build a report generation system that takes scan results and produces beautiful, clear, downloadable PDF reports. Also build an AI-powered recommendations engine that provides step-by-step fix instructions tailored to the organization's tech stack.

---

## Task 1: AI-Powered Report Narrative

Use Gemini API (or Grok as fallback) to generate human-readable report content from raw scan data.

### Report Narrative Generation:
```python
# Input: scan results (all check results, scores, findings)
# Output: structured narrative sections

# Prompt concept:
# "You are a cybersecurity advisor writing a security report for a non-technical
#  NGO director in Azerbaijan. The report should be clear, actionable, and avoid
#  jargon. Use simple language and analogies where helpful.
#
#  Given these scan results for [url]:
#  [structured scan data]
#
#  Generate:
#  1. Executive Summary (2-3 sentences: overall security posture, top priority)
#  2. What's Going Well (list things that passed — positive reinforcement)
#  3. Critical Issues (plain-language explanation of each critical/high finding)
#  4. Recommended Actions (numbered list, prioritized by impact, with estimated
#     difficulty: Easy/Medium/Hard and estimated time)
#  5. Next Steps (what to do after fixing the critical issues)"
```

### Recommendation Engine:
For each finding, generate a specific, actionable fix:

```python
# Example output for "Missing Content-Security-Policy header":
{
  "finding": "Missing Content-Security-Policy header",
  "severity": "high",
  "plain_language": "Your website doesn't have a rule telling browsers what content is allowed to load. This means attackers could inject malicious scripts into your pages.",
  "analogy": "Think of it like a building without a guest list — anyone can walk in.",
  "fix_steps": [
    "1. Contact your web developer or hosting provider",
    "2. Ask them to add this line to your server configuration:",
    "   Content-Security-Policy: default-src 'self'; script-src 'self'",
    "3. Test your website after the change to make sure everything still works",
    "4. If you use WordPress, install the 'HTTP Headers' plugin and configure CSP there"
  ],
  "difficulty": "medium",
  "estimated_time": "30 minutes with a developer",
  "cms_specific": {
    "wordpress": "Install the 'HTTP Headers' plugin → Settings → Security Headers → Enable CSP",
    "generic": "Add the header in your web server config (Apache .htaccess or Nginx server block)"
  }
}
```

### CMS-Specific Recommendations:
If CMS was detected in Phase 2, tailor fix instructions:
- **WordPress**: Reference specific plugins, wp-config.php settings, .htaccess rules
- **Joomla**: Reference Joomla admin settings, extensions
- **Generic/Unknown**: Provide server-level instructions (Apache/Nginx)

## Task 2: PDF Report Generation

### Report Structure:
```
1. Cover Page
   - CivicGuards logo
   - "Security Assessment Report"
   - Organization name
   - Website URL
   - Scan date
   - Overall score (large, color-coded)

2. Executive Summary
   - 2-3 paragraph overview
   - Score gauge graphic
   - Key stats: X critical, X high, X medium, X low, X passed

3. Score Breakdown
   - Category scores (SSL: A, Headers: D, CMS: B, etc.)
   - Visual bar chart

4. What's Working Well (green section)
   - List of passed checks with brief explanation

5. Issues Found (sorted by severity)
   - For each issue:
     - Severity badge
     - Title
     - Plain-language description
     - Why it matters
     - How to fix it (step-by-step)
     - Difficulty rating
     - Estimated time to fix

6. Action Plan (prioritized)
   - Numbered list of recommended actions
   - Priority order (quick wins first, then harder fixes)
   - Timeline suggestion (Week 1: critical fixes, Week 2: high fixes, etc.)

7. Appendix: Technical Details
   - Raw findings for technical staff
   - Full header analysis
   - Port scan results
   - DNS records

8. About CivicGuards
   - Brief description
   - "This report was generated by CivicGuards — free security scanning for civil society"
   - Contact info and website
```

### PDF Generation:
```python
# Use reportlab or weasyprint for PDF generation
# pip install reportlab   OR   pip install weasyprint

# Approach 1 (recommended): Generate HTML report → convert to PDF with weasyprint
# This gives full CSS control for beautiful formatting

# Approach 2: Use reportlab for programmatic PDF construction
# More control but more verbose code

# The HTML→PDF approach is recommended because:
# 1. Easier to style with CSS
# 2. Can reuse the web report design
# 3. Supports charts/images easily
# 4. The web version of the report doubles as a shareable link
```

### Backend Endpoints:
```
GET  /api/v1/security-scans/{scan_id}/report     — Generate/get PDF report
GET  /api/v1/security-scans/{scan_id}/report/html — Get HTML version of report
POST /api/v1/security-scans/{scan_id}/report/generate — Trigger AI narrative generation
```

## Task 3: Web-Based Report View

**Location**: `/dashboard/scan/[scanId]/report`

A beautiful, printable web version of the report (same content as the PDF):
- Clean, white-background design (switches from dark dashboard to light report)
- Proper print CSS for browser printing
- "Download PDF" button floating at top
- "Share Report" button (generates a unique public URL)
- Responsive — works on mobile for sharing with colleagues

### Shareable Report Links:
- Generate a unique token for each report: `/report/[token]`
- Public page (no auth required) showing the report
- Organization can share with their developer, hosting provider, or board
- Optional: expire after 30 days
- Optional: password-protect the link

## Task 4: Comparison Reports

When an organization runs multiple scans over time:

**Comparison View** (`/dashboard/scan/compare`):
- Select 2 scans of the same URL
- Side-by-side comparison:
  - Score change (72 → 85, +13 improvement)
  - New issues found
  - Issues resolved
  - Issues unchanged
- Visual diff: green for improvements, red for regressions
- "Progress Report" showing security posture over time

### Trend Chart:
- Line chart showing security score over time for a URL
- Helps organizations see improvement after implementing recommendations
- Great for demonstrating impact to grant reviewers
